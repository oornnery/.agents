# .plan

Implementation plans for features and structural changes.

Use `.plan/` to store phased, reviewable implementation documents before coding starts. Each plan names specific files, interfaces, and boundaries, and lists verifiable success criteria.

Rules:

- one plan per feature or coherent change
- name specific files and interfaces, not vague areas
- each phase must be independently verifiable
- keep plans focused; link to `.spec/` and `TODO.md` for broader context
