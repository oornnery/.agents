# .arch

Architecture reference for agents.

Use `.arch/` for system boundaries, data flow, technology choices, and deployment model. Keep it concise and current. Do not store secrets, credentials, or speculative future states.

Contents:

- `ARCH.md`: living architecture document with examples
- `decisions/` (optional): create for formal ADRs when `ARCH.md` tables are not enough; durable decisions otherwise live in `.mem/decisions.md`
